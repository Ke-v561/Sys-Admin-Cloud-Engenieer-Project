## Definition of done

A task is complete only when you can:
- Perform the task yourself in your lab or a controlled cloud environment.
- Explain what you changed and why.
- Verify the expected result.
- Troubleshoot at least one failure or explain how you would diagnose it.
- Document the work with sanitized evidence.
- Clean up temporary resources and confirm no unnecessary cloud charges remain.

## Safety and security

- Use only systems you own or are explicitly authorized to administer.
- Keep your home network stable; isolate lab networks and make one change at a time.
- Never commit passwords, API keys, access tokens, private keys, connection strings, customer data, or sensitive screenshots.
- Use fictional names and synthetic data.
- Review cloud pricing before deploying resources. Budgets and alerts are not always hard spending caps.
- Stop, deallocate, or delete billable resources when not needed; verify related disks, IPs, snapshots, and storage are also handled.
- Do not run destructive experiments on work or production systems.

## Suggested weekly commitment

Three sessions per week, about two hours each:
1. Learn the concept.
2. Build it in the lab.
3. Break/test, troubleshoot, document, and review.
