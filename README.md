# Kev.exe — IT & Cloud Engineering Roadmap

Welcome! This repository starts from **zero cloud and zero home-lab experience**. You do not need an existing Proxmox server, cloud account, or certification to begin.

## How to use this repository

Follow the paths in order. Each stage uses the pattern **learn → practice → build → test → document → certification**. Certifications are the finish line of a learning path, not a separate bucket.

## Learning paths

1. [01 — Foundations & First Lab](Roadmaps/01-Foundations-and-First-Lab/ROADMAP.md) — basic lab concepts, safe setup, networking and virtualization.
2. [02 — Cloud Foundations → AZ-900](Roadmaps/02-Cloud-Foundations-AZ900/ROADMAP.md) — learn cloud concepts and finish with Azure Fundamentals.
3. [03 — Windows Systems Administration](Roadmaps/03-Windows-Systems-Administration/ROADMAP.md) — Windows, users, permissions, networking services and directory services.
4. [04 — PowerShell & IT Automation](Roadmaps/04-PowerShell-IT-Automation/ROADMAP.md) — build practical scripts and document them.
5. [05 — Azure Administration → AZ-104](Roadmaps/05-Azure-Administration-AZ104/ROADMAP.md) — learn Azure administration and finish with Azure Administrator Associate.
6. [06 — AWS Foundations](Roadmaps/06-AWS-Cloud-Foundations/ROADMAP.md) — optional AWS path, ending with Cloud Practitioner if it supports your goals.
7. [07 — Career Portfolio](Roadmaps/07-Career-Portfolio/ROADMAP.md) — turn completed work into evidence for job applications.

## Beginner rules

- Start at Path 01 even if some topics sound familiar; mark a task complete only after you can do and explain it yourself.
- You can begin with a regular Windows PC. Do not buy a server or paid cloud subscription just to start.
- Use free learning resources and local virtual machines where your hardware supports them. If it doesn't, document the lab design and use a safe alternative.
- Cloud services can cost money. Before creating anything billable, set a budget/alert where available, understand the pricing, and delete resources when finished. Alerts are not always hard spending caps.
- Use fictional users and synthetic data. Never commit passwords, API keys, tokens, private keys, customer information, or unredacted screenshots.

## Definition of done

For each project: explain the goal, record the design, perform the task, test the result, capture sanitized evidence, write down one issue and how you resolved it, and publish the documentation here.
