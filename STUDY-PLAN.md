# Weekly Study Plan

## Default cadence: 6 hours per week

| Session | Duration | Focus | Required output |
|---|---:|---|---|
| Session A | 2 hours | Learn one concept from official docs/course | Notes and 5 self-test questions |
| Session B | 2 hours | Reproduce concept in home lab | Working configuration or lab evidence |
| Session C | 2 hours | Test, break, troubleshoot, document | Troubleshooting entry and GitHub commit |

Optional: 30-minute weekly review.

## Session checklist

- [ ] Write the objective before starting.
- [ ] Read/watch the learning material.
- [ ] Build the concept yourself without blindly copying.
- [ ] Verify the expected result.
- [ ] Test one failure scenario.
- [ ] Record commands, errors, root cause, and fix.
- [ ] Remove secrets from screenshots/configuration.
- [ ] Commit the documentation and update `TRACKER.md`.

## Weekly review

At the end of each week, answer:
1. What can I now do that I could not do last week?
2. Can I explain it without reading the instructions?
3. What failed, and how did I troubleshoot it?
4. What still feels unclear?
5. What is the next smallest practical step?

## Pace adjustment

- If you have four hours: complete one learning session and one practical session; carry documentation into the next week.
- If you have eight or more hours: add a second troubleshooting scenario or repeat the lab from a clean starting point.
- Do not skip hands-on work to finish a certification faster.
